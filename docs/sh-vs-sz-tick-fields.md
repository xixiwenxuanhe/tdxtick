# 沪深逐笔字段语义与「沪市 45% 无法关联」的根因

> 结论日期：2026-09-11，数据：20260911 全天，沪市 5 只 + 深市对照。

## 一句话结论

> 根因 = **两市交易所行情发布规则不同**（不是通达信 bug，也不是本工具抓取问题）：
> 上交所不发布「立即全部成交」的主动方委托（LDDS §4.3.1），深交所发布全部委托（STEP §4.4.5）。

**沪市**：TDX 的"逐笔委托"实际是**委托簿挂单流**——只含"进入订单簿的挂单（被动方）"，
**不含"到达即成交的主动方委托"**。所以用成交里的买卖订单号去委托流里查，会缺约 45%。
**深市**：是**完整逐笔委托**（含主动方），因此 100% 可关联，订单账本重建可用。

## 两市字段语义对照

| 项 | 深市 | 沪市 |
|---|---|---|
| 委托 `order_number` | = `sequence`（业务/委托序号） | = 记录的 **bid(买)/ask(卖)** 字段，另一个为 **0**；`sequence` 是**业务序号**，与订单号独立 |
| 订单号作用域 | 每股、连续 | **频道级共享**（号段稀疏：600000 在号段 1–1000 里只有 6 个号） |
| 委托 `order_type_raw` | `'2'` 为主，另有 `'1'` / `'U'` | 全部 `'0'` |
| 撤单行 `price` | `0`（导出器补 `order_price`） | **非 0，且等于原委托价**（交易所原始字段） |
| 委托 `quantity_shares` | **原始委托量** | 对"主动成交后又挂单"的委托是**剩余量**：`原始量 = 记录量 + 该委托的即时成交量` |
| 集合竞价 | — | 委托在 `09:15` 起，成交 `09:25` 起 |
| 特殊记录 | — | 有 19 条 `action='P'`（盘后固定价格，channel 103） |

## 沪市委托记录的 `quantity_shares` 是"成交后剩余量"，不是原始委托量

上交所规则（LDDS §4.3.1 说明第 4 条）里"先发成交、再发成交后的**剩余**新增委托订单"，
落到字段上就是：

> 对"主动成交后又挂单"的委托，委托记录的 `quantity_shares` **本身就是成交后的剩余量**，
> 不是原始委托量。

规则：

```
原始委托量 = 委托记录量 + 该委托的即时成交量
（即时成交量 = 与委托记录同毫秒、且引用同一 order_number 的成交量）
```

可复现样例（`600000` / `20260911`，order_number `439537`）：

```
09:30:00.270  委托  side=S  qty=23,500  @9.34  seq=540753
09:30:00.270  成交  ask    10,000  @9.34   ← 与委托记录同毫秒
09:30:00.270  成交  ask     5,000  @9.34   ← 与委托记录同毫秒
09:30:03.140 ~ 09:30:05.480   后续成交 23,500
成交合计 38,500 = 15,000(即时成交) + 23,500(记录量) ✓
```

**量化（`600000` / `20260911` 全天）**

| 项 | 数量 |
|---|---|
| 全部委托 | 61,246 |
| 委托记录同毫秒即有成交（= 到达即成交的主动委托） | **784**（1.3%） |
| 被低估的委托量合计 | **5,020,934 股** |
| 占总委托量比例 | **3.5%** |
| 其中暴露成"成交量 > 委托量"的 | 637（1.04%） |
| └ 逐个验证「记录量 + 同毫秒成交量 == 守恒所需」：精确相等 | 590（92.6%） |
| └ 修正后偏多（毫秒内多笔订单撞车） | 47 |
| └ 修正后仍不足（**真透支**） | **0** |
| 深市对照 `002971` | 透支 0，无此现象 |

**为什么这条重要**：这 784 个订单只占 1.3%，但贡献了当天 **15.6% 的成交股数** —— 全是
活跃大单，不是边角案例。沪市任何以"委托量"为口径的统计（大单识别、挂单规模、撤单率分母）
在这批订单上会**系统性低估**，而大单恰恰是订单流分析最关心的部分。

**给调用方的明确口径**：沪市委托记录的 `quantity_shares` 是**成交后剩余量**，
**不得直接当作原始委托量**。

**修正取值时的建议**

- 锚点请用**合并流里 `sequence` 的邻接关系**（成交记录紧邻其后的委托记录），
  不要用毫秒 —— 上面 47 个偏差就是毫秒撞车造成的。
- API 已在 `summary` 层标注，可直接据此分支（history 与 live 都有）：
  - 沪市 `coverage: "resting_only"`、`quantity_semantics: "remaining_after_immediate_fill"`
  - 深市 `coverage: "full"`、`quantity_semantics: "original"`

## 对"订单级账本重建"的影响

- **深市**：`委托量 = 成交量 + 撤单量 + 剩余量` 可闭环（已由使用方验证通过）。
- **沪市**：**无法**用 TDX 委托流做完整账本——主动方委托缺失。只能做
  「被动挂单 + 成交」的统计（被动撤单率、挂单存续、主动单聚合成交额）。

## 根因已定论：**上交所发布规则如此**

依《上海证券交易所 LDDS 系统竞价 Level-2 行情接口说明书》(2.0.15) §4.3.1「竞价逐笔合并数据」(UA5803)：

> 4. 在连续竞价阶段，同一笔委托产生的主动成交及剩余新增委托订单数据，先发送成交数据，再发送成交后的剩余新增委托订单数据，**之后再产生的剩余委托订单数据不再发送**；
>
> 3. 集合竞价及停牌期间不发送逐笔类数据，到集合竞价或停牌结束时统一发送期间的数据，**先发送委托订单数据，再发送成交数据**和产品状态订单数据；

对应我们的实测：

| 规则 | 实测对应 |
|---|---|
| 到达即**全部成交**的主动委托 → 不发委托记录 | 连续竞价 93% 的成交只有被动方在委托流 |
| 只**部分成交**的主动委托 → 成交后补发一条「剩余量」委托 | 连续竞价 7% 双边命中（`both`） |
| 集合竞价 → 结束时先补发全部委托、再发成交 | 集合竞价 480 笔**双边全部命中** |
| 后续剩余变化不再发送 | 参与多笔成交的挂单在委托流里看不到完整过程 |

深市对照：《深圳证券交易所 STEP 行情数据接口规范》(Ver1.17) §4.4.5 把逐笔委托(UA201)与逐笔成交(UA202)
放在**同一数据流、统一连续编号**，UA201 携带 `Price`/`OrderQty`（**原始委托价与委托量**），
**每一笔委托都会发布** → 深市 100% 可关联、`委托量 = 成交量 + 撤单量 + 剩余量` 可闭环。

**所以：不是通达信的问题，也不是本工具抓取链路的问题 —— 是两市交易所行情发布规则不同。**

## 「是我们的抓取链路，还是通达信本身？」—— 排除过程

### 证据 1：我们的解码无损

`T0002/zst_cache/sh600000_20260911.tck` 头里 `uncompressed_bytes = 5,061,708`，
`5,061,708 / 36 = 140,603`，与实际解出的记录数**完全相等**（`len(data) % 36 == 0`）。
字节层没有任何记录丢失。我们只做「解压 + 按 36B 切记录」，没有任何过滤。

### 证据 2：软件自己的委托数据 == 我们抓到的数据（集合完全相等）

软件画「逐笔委托」页面用的内存缓冲区（`TdxW.exe+0x760a80`，count@`+0x254`，data@`+0x3d0`）
在 2026-09-11 14:41 被抓过一份 **603105 的完整 dump（313,600 条）**。
把它的**订单号集合**与同股票、同时间上限的 tck 逐号对撞：

```
软件显示缓冲区 委托号集合 = 56,357
tck 重放文件   委托号集合 = 56,357      → 双向差集都是 0
软件显示缓冲区 撤单号集合 = 21,974
tck 重放文件   撤单号集合 = 21,974      → 双向差集都是 0
```

再用显示缓冲区的号码重做成交关联：
`both 6516 / onlyS 25835 / onlyB 23042 / none 0` —— 与 tck 是**同一个「挂单流」形态**。

即：**软件界面背后那份数据本身就没有主动方委托**，不是我们抓漏。

### 证据 3：显示缓冲区是服务器直接喂的

前次逆向已确认：`0x055e`（服务器逐笔委托数据帧）到达的时刻，与 `0x760a80` 委托渲染的
count 增长**一一对应**（帧到 → 数毫秒后 count+1..3）。所以「界面缓冲区 == 服务器委托流」，
中间没有第三方加工层。

### 当时未闭合的一环（现已由上交所规则闭环）

上面三条只能证明「**从服务器到界面、到我们**」这条链上**没有任何丢失**。当时无法区分：

1. 上交所 L2 的委托流本身只含挂单；
2. TDX 服务端做了过滤/抽样。

现已由上交所官方规范 §4.3.1 证实：**是第 1 种 —— 交易所本身就不发布「立即全部成交」的主动委托。**
